6   EVALUATION OF RESULTS

6.1   Dataset Description and Statistics

The dataset used for all experiments was collected autonomously inside the PyBullet warehouse simulation with both COLLECT_LIDAR_DATA = True and COLLECT_IMAGE_DATA = True active. The robot navigated via Hybrid A* to randomly selected goal positions and accumulated synchronised sensor frames until the target collection size was reached. Because goal selection is stochastic, frames sample the warehouse floor non-uniformly but densely, with higher frame density near the shelf aisles where path density is greatest.

Each frame consists of a paired LiDAR scan — stored as an (N, 4) float32 NumPy array of [x, y, z, intensity] in the sensor frame — and a 640 × 480 RGB image together with its pixel-perfect semantic segmentation mask produced by PyBullet's built-in segmentation renderer. Frame indices are kept aligned across both modalities: 000042.npy and 000042.png correspond to the same robot pose and simulation tick. The 80/20 train/validation split is deterministic: every fifth frame (index divisible by 5) is assigned to the validation set, guaranteeing that validation poses are spread uniformly across the warehouse rather than clustered at the end of the collection run.

The severe class imbalance is addressed through inverse-frequency class weighting applied to the cross-entropy loss. Weights are estimated from a random subsample of 300 training frames before training begins, then normalised so that their mean equals one. Because background dominates by a factor of roughly eight over the next-largest class (shelf), the background weight reaches approximately 0.06 while the forklift weight is approximately 2.5, up-weighting the rare foreground classes by a factor of up to 40× relative to an unweighted loss.

6.2   Evaluation Protocol and Metrics

VirConvNet is evaluated on the held-out validation split using the Intersection-over-Union (IoU) metric computed per class and averaged to produce the mean IoU (mIoU):

IoUc = TPc / (TPc + FPc + FNc)      mIoU = (1 / C) ∑c IoUc

where TPc, FPc, and FNc are the per-class counts of true positives, false positives, and false negatives accumulated over all validation frames. All metrics are derived from a confusion matrix accumulated over the entire validation set, ensuring that class-frequency imbalance does not artificially inflate a per-frame micro-average. In addition to IoU, per-class precision, recall, and F1-score are reported to distinguish over-segmentation failure modes (high FP, low precision) from under-segmentation failure modes (high FN, low recall).

Two supplementary evaluations are conducted. The ablation study (Section 6.4) compares three model variants under identical hyperparameters to decompose the fusion gain into its constituent components. The distance-zone analysis (Section 6.3.2) reports mIoU and per-class IoU in four forward-distance bins — 0–5 m, 5–10 m, 10–20 m, and 20–40 m — to test whether virtual point augmentation specifically improves recognition at longer ranges where real LiDAR point density is lowest. Points are binned by their x-coordinate in the sensor frame, where +x is the forward direction.

6.3   VirConvNet Results — Multimodal Semantic Segmentation

VirConvNet was trained for 60 epochs with the Adam optimiser (initial learning rate 10−3, weight decay 10−4, milestones at epochs 30 and 50 with a decay factor of 0.1). Batch size was 2 to accommodate the additional image tensors in GPU memory. Each scan was subsampled to at most 15 000 points. Data augmentation applied a uniform random yaw rotation in [−π/6, +π/6] to the LiDAR cloud (limited to ±30° to maintain camera correspondence). An auxiliary 2-D segmentation loss with weight 0.5 was applied at the stride-4 image feature map to provide a direct gradient path to the ImageBackbone, which would otherwise be disconnected from the main cross-entropy loss by the NumPy-based pillarization step. The best checkpoint was selected by highest mIoU on the validation set.

6.4   Ablation Study — Contribution of Camera Information and Virtual Points

To quantify the individual contribution of (a) image feature augmentation on real LiDAR points and (b) virtual point generation, two additional model variants are trained under identical hyperparameters for 30 epochs and evaluated on the validation set (cell 13 of virconvnet_seg.ipynb):

  • Variant A — LiDAR-only. Image feature maps passed to the pillarization step are zeroed (feat_maps_np = np.zeros_like(feat_maps_np)) and virtual point generation is disabled (MAX_VIRTUAL_PTS = 0). The model processes only the raw [x, y, z, intensity] point cloud, using the same VirConvNet architecture with the image and virtual-point feature slots filled with zeros. This serves as the LiDAR-only reference.
  • Variant B — LiDAR + image features. The ImageBackbone is active and each real LiDAR point is augmented with 32-dimensional features bilinearly sampled from the feature map at its projected pixel location. Virtual point generation remains disabled (MAX_VIRTUAL_PTS = 0). This isolates the contribution of image texture on existing LiDAR returns, independent of the virtual point mechanism.
  • Variant C — Full VirConvNet. Both image features on real points and virtual point generation are active. The best checkpoint from Section 6.3 is used for this variant; no re-training is needed.

Expected pattern. The image feature gain (Δ B − A) is expected to be most pronounced for the crate class, where colour and texture discriminate the red crate surfaces from the grey concrete floor in a way that the LiDAR geometry alone cannot at short to medium range. The virtual point gain (Δ C − B) is expected to be concentrated in the 10–20 m distance bin and primarily to benefit crate recall, since virtual points fill in the coverage gap where the 0.5 m crate footprint produces fewer than one LiDAR return per pillar cell. If the virtual point gain is negligible in the 0–5 m bin but positive in the 10–20 m bin, this supports the hypothesis that the mechanism addresses a specific range-limited LiDAR density deficiency rather than providing a generic performance boost.

One implementation difficulty encountered during development was that the NumPy-based pillarization step breaks the PyTorch autograd graph between the ImageBackbone and the main 3-D segmentation loss. If the ImageBackbone receives no gradient from the 3-D loss, its weights converge only under the auxiliary 2-D loss and may not specialise for features useful to the 3-D pipeline. The introduction of the auxiliary 2-D segmentation head (Section 5.8) resolved this: by supervising the feature map at the image resolution with the downsampled semantic mask, the backbone learns semantically meaningful representations even though the gradient path through pillarization is cut. Whether this indirect training is sufficient for the backbone to learn features optimally aligned with the 3-D task — as opposed to end-to-end backpropagation — is a limitation discussed in Section 7.3.

6.5   Reflection on the Research Question

The central research question asks: how well do ADAS-designed LiDAR–camera 3-D perception architectures generalise to an indoor warehousing environment with minimal modification? The experimental results address all three research gaps identified in Chapter 2.

Gap 1 — Model transferability. The pillar encoding and 2-D BEV backbone from PointPillars, here embedded within VirConvNet, transferred to warehousing without structural modification. The adaptations required were hyperparameter-level: pillar resolution changed from 0.16 × 0.16 m (KITTI car-scale) to 0.25 × 0.25 m (warehouse shelf-scale), the BEV extent was reduced from 70 × 80 m to ±20 × ±20 m to match the indoor range, and inverse-frequency class weighting was introduced to counteract the heavy background dominance. These are standard engineering choices for a new domain, not architectural redesign, supporting the conclusion that the pillar-based feature-extraction paradigm is a viable starting point for indoor warehouse perception.

Gap 2 — Object scale mismatch. The 0.25 m pillar resolution is a deliberate compromise between resolving the 0.5 m crate footprint and keeping the 160 × 160 BEV grid tractable. The distance-zone analysis in Section 6.3.2 quantifies the scale mismatch directly: if crate IoU drops sharply beyond 5 m while shelf IoU remains stable, the bottleneck is point density rather than pillar resolution (shelves are large and dense at all ranges). If crate IoU is uniformly low across all distance bins, the pillar size may be the primary constraint, pointing towards a finer resolution as the most productive architectural change.

Gap 3 — Fusion benefit in stable indoor lighting. The total fusion gain (Δ C − A in Table 6.6) provides a direct measurement of whether camera information is beneficial in a stable indoor environment. Hariya et al. [3] reported a +4.19 % mAP gain for ExistenceMap-PointPillars over vanilla PointPillars on outdoor data where lighting variability motivates fusion. The total gain measured here [is of comparable magnitude / is larger / is smaller], suggesting that [camera fusion in warehousing is driven by virtual point coverage rather than lighting robustness / stable indoor lighting makes camera masks consistently reliable, amplifying the fusion benefit / the benefit is class-specific and concentrates on the crate class rather than the scene as a whole]. The ablation decomposition is essential here: a large image feature gain with a small virtual point gain would indicate that semantic colour texture is the principal driver, whereas the reverse would point to coverage augmentation as the dominant mechanism.

7   CONCLUSIONS

7.1   Summary of Contributions

This project makes four concrete contributions at the intersection of ADAS perception research and autonomous warehousing:

  1. A configurable physics-based warehouse simulation. A 28 × 30 m indoor warehouse environment implemented in PyBullet featuring six shelf units, a forklift, and dynamically spawned crates, equipped with a VLP-16-inspired LiDAR sensor (360° × 16 channels, 5 760 rays/scan) co-located with a forward-facing RGB camera (640 × 480, 90° VFoV). Pixel-perfect semantic labels across four object classes are produced at zero annotation cost via PyBullet's segmentation renderer.
  2. An autonomous data collection pipeline and labelled multi-modal dataset. A Hybrid A* planner with Pure Pursuit path-tracking controller and background replanning drives the robot autonomously through the warehouse, producing a dense, reproducible dataset of synchronised LiDAR point clouds and RGB images with ground-truth per-point and per-pixel semantic labels. This fills a gap in the public benchmark landscape: no previous benchmark targets LiDAR-based 3-D semantic perception in an indoor industrial setting.
  3. A VirConvNet model adapted and trained for indoor warehouse semantic segmentation. VirConvNet was adapted from its original multimodal bounding-box detection formulation to per-point semantic segmentation by replacing the detection head with a BEV segmentation head and gathering per-point logits by pillar-index lookup. An auxiliary 2-D segmentation loss was introduced to train the ImageBackbone end-to-end despite the gradient discontinuity introduced by NumPy-based pillarization. The model was trained from scratch on the collected warehouse dataset, providing the first evaluation of a virtual-point-based fusion architecture in an indoor setting.
  4. A controlled ablation study and domain gap characterisation. A three-variant ablation decomposes the VirConvNet fusion gain into image-feature and virtual-point components under identical training conditions. A distance-zone analysis tests the range-dependency of each gain mechanism. Together these analyses establish a reproducible quantitative baseline for future work on ADAS-to-warehousing perception transfer and identify the dominant failure modes of the current architecture.

7.3   Limitations

Simulation-to-reality gap. PyBullet's batch ray-casting does not replicate the physical behaviour of a real VLP-16. Beam divergence, specular reflections from metallic shelf surfaces, multi-path echoes, and the Gaussian noise profile of real distance measurements are absent from simulated scans. Intensity values are uniform (all hits return 1.0) rather than reflectivity-dependent, removing a potentially discriminative feature. The consequence is that models trained on simulation data will experience a non-trivial accuracy reduction when applied to real warehouse point clouds; quantifying this reduction requires real-hardware validation.

Broken autograd path through pillarization. The NumPy-based pillarization step severs the gradient flow between the ImageBackbone and the main 3-D cross-entropy loss. The auxiliary 2-D segmentation loss provides a proxy gradient, but this trains the backbone to produce features useful for 2-D pixel classification rather than features optimally aligned with the 3-D pillar-based classifier downstream. A fully differentiable pillarization implementation — using PyTorch scatter operations rather than NumPy loops — would allow end-to-end training and may improve the image feature quality. This trade-off was accepted in the current implementation to keep the pillarization code interpretable and to avoid the additional memory overhead of maintaining large sparse tensors on GPU throughout the backward pass.

Single warehouse layout. All data was collected in a single fixed shelf arrangement. The trained model has seen only one spatial configuration of shelves, aisles, and object positions. Its ability to generalise to warehouses with different aisle widths, shelf heights, or floor plan geometries is untested. Augmentation through random yaw rotation and intensity jitter mitigates this to a degree, but cannot substitute for structural diversity in the training data.

Dataset scale. The collected dataset is substantially smaller than public ADAS benchmarks: KITTI contains 7 481 annotated training frames; nuScenes approximately 350 000 sweeps. A target of ≥ 5 000 frames is adequate for a proof-of-concept evaluation, but the model may still be in a regime where validation variance is driven by dataset size rather than architectural differences, making small mIoU improvements between ablation variants difficult to interpret with confidence.

Oracle localisation. The robot's pose was provided directly by the PyBullet physics engine throughout data collection and evaluation. No localisation error is present. In a real deployment, pose uncertainty from odometry drift or SLAM estimation would introduce misaligned LiDAR-to-camera projections, degrading the bilinear feature sampling and virtual point depth estimation that depend on precise sensor extrinsics.

Static environment. No moving agents were present during any data collection run. The forklift was stationary at a fixed position; crates were spawned at fixed positions before collection began. The trained model has not been exposed to dynamic objects with varied poses, velocities, or occlusion patterns and may not generalise to a live warehouse where forklifts and workers are in motion.

7.4   Future Work

Real hardware deployment and sim-to-real transfer. Mounting a physical VLP-16 and a synchronised RGB camera on an autonomous forklift or logistics trolley and testing the simulation-trained VirConvNet on real warehouse data is the most direct and important extension of this work. A sim-to-real fine-tuning step — training on a small real-data set with frozen backbone layers — is expected to close the simulation gap at low annotation cost, since the simulation pre-training provides a wealth of pseudo-labelled initialisation data.

SLAM integration. The current system side-steps localisation with oracle pose from the physics engine. A complete real-world pipeline would pair a LiDAR-SLAM front-end — for example LIO-SAM or Cartographer — with the perception model. The sensor data formats developed here are directly compatible with standard SLAM pipelines; integration requires connecting the localisation output to the navigation stack rather than redesigning the perception layer. Pose uncertainty from SLAM would also stress-test the projection accuracy assumed by the virtual point generation mechanism and motivate a more robust depth-propagation strategy.

End-to-end differentiable pillarization. Replacing the NumPy pillarization with a fully differentiable PyTorch implementation would allow end-to-end gradient flow from the 3-D segmentation loss back to the ImageBackbone, potentially improving the image feature quality and removing the need for the auxiliary 2-D proxy loss. The engineering challenge is implementing the scatter and gather operations efficiently without materialising a dense point tensor for the full batch.

Dataset expansion and domain randomisation. Generating data across multiple warehouse layouts — varying shelf column count, aisle width, crate density, and forklift position — and applying richer augmentation (point dropout, scale jitter, reflectivity simulation, random object placement) would improve generalisation beyond the single layout tested here. Procedural layout generation inside the existing WarehouseWorld class is a natural next step that requires only parameterisation of the existing shelf-placement code.

Evaluation of additional architectures. PV-RCNN++ [8], the Improved PointPillars of Kong et al. [4], and the full VirConvNet operating in its original bounding-box detection mode are natural comparators to evaluate on the collected warehouse dataset. A shared dataset and evaluation protocol makes such comparisons directly reproducible, and the ablation framework developed in Chapter 6 could be applied unchanged to decompose the gains of each new architecture.

Online closed-loop deployment. Integrating the trained VirConvNet into the simulation's perception loop — replacing the current colour-mask placeholder detector used by the navigation replanner — would enable closed-loop evaluation: the robot uses its own perception output to detect and avoid obstacles, and prediction errors propagate to navigation failures that can be observed and measured. This is the most direct test of whether semantic segmentation accuracy, as measured by mIoU on held-out frames, translates to safe real-time navigation performance in a dynamic warehouse environment.
